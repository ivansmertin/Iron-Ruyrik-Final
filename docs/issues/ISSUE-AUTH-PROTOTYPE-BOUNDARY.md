# Issue: Границы прототипа аутентификации (Auth Prototype Boundary)

**Статус**: Open (Known Prototype Boundary)  
**Компонент**: Backend Auth / Frontend Session  
**Обнаружено на этапе**: M09 / M12 (Visual Migration «Железный Рюрик»)  
**Дата**: 12.09.2026  

---

## 1. Описание проблемы
Приложение запущено в режиме прототипа без полноценного сервера аутентификации (JWT, OAuth, SMS-код). По умолчанию клиент работает в профиле Алексея (`user_id = 'u-1'`). В ранней версии приложения существовала модалка логаута, которая выдавала фиктивное сообщение «В прототипе вы остаётесь в профиле Алексея».

## 2. Честное отражение в UI
- На экране профиля (`ProfilePage.tsx`) фиктивная модалка логаута полностью устранена.
- Пункт меню оформлен как неинтерактивная строка с честным описанием:
  `Выход из профиля / Автономный режим без серверной авторизации`.
- Приложение не обещает неподтвержденный серверный логаут/логин и не вводит пользователя в заблуждение.

## 3. Рекомендации для Product/Backend
1. Внедрить модуль авторизации по номеру телефона / Telegram Login Widget.
2. Реализовать `POST /api/v1/auth/logout` с отзывом сессионных токенов.
